# بخش ۱ — مفاهیم پایه از صفر

این بخش رو با حوصله بخون؛ همه‌چیزِ بقیه‌ی سند به همین‌ها برمی‌گرده.

## ۱.۱ سیگنال چیست؟

**سیگنال** یعنی هر کمیتی که در طول زمان (یا مکان) تغییر می‌کنه و اطلاعات حمل می‌کنه.

- صدا: فشار هوا که با زمان تغییر می‌کنه → سیگنال **یک‌بعدی** `x(t)`
- تصویر: روشنایی که با مکان (سطر، ستون) تغییر می‌کنه → سیگنال **دوبعدی** `I[r, c]`

این دیدگاه دلیل اینه که یک درس واحد هم به صوت می‌پردازه هم به تصویر: ابزارها یکی‌ان، فقط بُعد فرق می‌کنه.

## ۱.۲ نمونه‌برداری (Sampling)

کامپیوتر نمی‌تونه سیگنال پیوسته ذخیره کنه؛ به‌جاش در فاصله‌های زمانی مساوی از سیگنال «نمونه» می‌گیره:

```
x[n] = x(n / fs)
```

که `fs` **نرخ نمونه‌برداری** (sample rate) است. فایل‌های ما `fs = 44100` نمونه در ثانیه دارن (استاندارد CD).

**قضیه نایکوئیست-شانون**: با نرخ `fs` فقط می‌شه فرکانس‌های تا `fs/2` رو درست نمایش داد. پس فایل‌های ما حداکثر تا ۲۲٬۰۵۰ هرتز محتوا دارن. (گوش انسان هم تقریباً تا ۲۰ کیلوهرتز می‌شنوه — برای همین ۴۴٫۱ استاندارد شد.)

## ۱.۳ دسیبل (dB)

گوش انسان نسبت‌ها رو می‌شنوه نه تفاضل‌ها؛ برای همین دامنه‌ها رو لگاریتمی گزارش می‌کنیم:

```
dB = 20 × log10(دامنه / دامنه‌ی مرجع)
```

- هر **۲۰dB** یعنی ۱۰ برابر دامنه.
- **dBFS** یعنی مرجع = تمام‌مقیاس (دامنه ۱٫۰). پس سیگنالی با RMS برابر ۰٫۱ می‌شه 20-. dBFS.
- اعداد منفی‌تر = ضعیف‌تر. مثلاً کف نویز 60- dB یعنی خیلی آروم.

## ۱.۴ حوزه فرکانس و تبدیل فوریه

**ایده‌ی مرکزی کل درس**: هر سیگنالی رو می‌شه به صورت جمعِ سینوسی‌هایی با فرکانس‌های مختلف نوشت. «تبدیل فوریه» همین تجزیه رو انجام می‌ده: به ما می‌گه در هر فرکانس چقدر انرژی هست.

چرا مهمه؟ چون خیلی از آرتیفکت‌ها در **حوزه زمان** قاطیِ گفتار هستن ولی در **حوزه فرکانس** جدا می‌شینن:

- هومِ برق شهر: فقط در ۵۰ هرتز و مضارب آن
- هیس (نویز پس‌زمینه): پخش در همه فرکانس‌ها، ولی گفتار فقط در ۳۰۰ تا ۳۴۰۰ هرتز قوی است
- تونِ موسیقی انتظار: خط باریک در یک فرکانس ثابت

وقتی آرتیفکت و سیگنال در فرکانس جدا باشن، حذف آرتیفکت «راحت» است: فیلتر می‌زنیم.

## ۱.۵ STFT و اسپکتروگرام — مهم‌ترین ابزار مسئله ۱

مشکل تبدیل فوریه‌ی ساده: می‌گه «چه فرکانس‌هایی هست» ولی نمی‌گه **کِی**. گفتار مدام عوض می‌شه (به این می‌گن سیگنال **نامانا** / non-stationary).

راه‌حل: **تبدیل فوریه کوتاه-زمان (STFT)**. سیگنال رو به پنجره‌های کوچک هم‌پوشان تقسیم می‌کنیم (در پروژه: پنجره ۲۰۴۸ نمونه ≈ ۴۶ میلی‌ثانیه، گام/hop ۵۱۲ نمونه ≈ ۱۲ میلی‌ثانیه) و از هر پنجره فوریه می‌گیریم. نتیجه `X[k, m]`: انرژی فرکانس `k` در حوالی لحظه `m`.

اگه قدر مطلق این ماتریس رو مثل عکس نمایش بدیم (محور افقی = زمان، عمودی = فرکانس، رنگ = شدت به dB) می‌شه **اسپکتروگرام**. با نگاه به اسپکتروگرام هر آرتیفکت یک «امضا» داره:

| آرتیفکت | شکلش در اسپکتروگرام |
|---|---|
| کانال باند-محدود تلفن | قطع ناگهانی انرژی بالای ~۳٫۴ کیلوهرتز |
| نویز ایستا (هیس/هوم) | کف روشن ثابت / خط‌های افقی در فرکانس ثابت |
| کلیک و ترق‌تروق | خط‌های **عمودی** نازک تمام-باند |
| موسیقی انتظار | خط‌های **افقی** ممتد (نت‌های کشیده) |
| سکوت | ستون‌های سیاه |

## ۱.۶ فیلتر و سیستم LTI

**فیلتر** سیستمی است که بعضی فرکانس‌ها رو عبور می‌ده و بعضی رو تضعیف می‌کنه. فیلترهای این پروژه **خطی و تغییرناپذیر با زمان (LTI)** هستن؛ رفتارشون کاملاً با «پاسخ فرکانسی» توصیف می‌شه: نموداری که می‌گه هر فرکانس چند dB تقویت/تضعیف می‌شه.

انواعی که استفاده کردیم:

- **میان‌گذر (band-pass)**: فقط بازه‌ای از فرکانس‌ها رو نگه می‌داره. ما ۳۰۰ تا ۳۴۰۰ هرتز (باند تلفن) رو نگه داشتیم.
- **ناچ (notch)**: عکس میان‌گذر ولی خیلی باریک — یک فرکانس مشخص رو «جراحی» حذف می‌کنه. پهنای آن با پارامتر Q کنترل می‌شه: پهنای 3dB- برابر `f0/Q`. با Q=35 در ۳۰۰۰ هرتز یعنی فقط ~۸۶ هرتز.

دو مفهوم مهم دیگه:

- **باترورث (Butterworth)**: طرحی از فیلتر که باند عبورش «حداکثر تخت» است — یعنی هیچ موج‌دار شدنی (ripple) در باند عبور نداره، پس رنگ صدا رو تغییر نمی‌ده. به همین دلیل انتخابش کردیم.
- **فاز صفر (`sosfiltfilt`)**: هر فیلتر IIR سیگنال رو کمی در زمان جابه‌جا/کج می‌کنه (اعوجاج فاز). اگر فیلتر رو یک بار رو به جلو و یک بار رو به عقب اعمال کنیم، اعوجاج‌های فاز همدیگه رو خنثی می‌کنن (و اثر دامنه دو برابر می‌شه). چون پردازش ما آفلاین است این کار ممکنه و کیفیتش بهتره. پسوند `sos` یعنی پیاده‌سازی به‌صورت «مقاطع مرتبه دو» که از نظر عددی پایدارتر از ضرایب یکجاست.

## ۱.۷ کانولوشن (برای تصویر)

در دو بُعد، فیلتر کردن یعنی لغزاندن یک پنجره‌ی کوچک (kernel) روی تصویر و ترکیب همسایگی هر پیکسل. جمع وزن‌دار → فیلترهای خطی (مثل بلور گاوسی)؛ min/max/میانه → فیلترهای رتبه‌ای (مثل فیلتر میانه و مورفولوژی). جزئیات در بخش ۳.

# بخش ۲ — مسئله ۱: بازسازی صوت مرکز تماس

## ۲.۱ صورت مسئله

سه ضبط مرکز تماس داریم که این خرابی‌ها رو دارن (طبق صورت پروژه):

1. **محدودیت باند** — کانال تلفن فقط ۳۰۰ هرتز تا ۳٫۴ کیلوهرتز رو رد می‌کنه.
2. **نویز آکوستیک** — نویز ایستا (هیس/هوم) + صداهای ضربه‌ای گذرا.
3. **اکو** — نسخه‌های تأخیردار و تضعیف‌شده‌ی گفتار.
4. **سکوت و موسیقی انتظار** — بلوک‌های هوای مرده یا آهنگ انتظار.
5. **نوسان بلندی صدا** — بلندی ناهماهنگ بین گوینده‌ها یا در طول زمان.

خواسته: خط لوله‌ای (pipeline) که گفتار رو جدا، تمیز و نرمال کنه + تحلیل قبل/بعد.

## ۲.۲ چیزی که واقعاً در داده‌ها دیدیم (EDA)

قبل از هر کاری داده رو «شناختیم» — این قدم در نمره هم هست (EDA؛ ۱۰ نمره) و همه‌ی تصمیم‌های بعدی از همین اومده:

| فایل | مدت | ویژگی‌های کلیدی که اندازه گرفتیم |
|---|---|---|
| `2.mp3` | ۲۱۴ ثانیه | عملاً صفر درصد انرژی بالای ۳٫۴kHz → **باند تلفنی**. ~۲۸٪ فریم‌ها سکوت. یک بلوک هوای مرده‌ی بزرگ حدود ثانیه ۶۸ تا ۱۰۲. |
| `3.mp3` | ۱۸۸ ثانیه | **بلند و پیوسته** (فقط ~۱٪ سکوت)، پهن‌باند (~۵٪ انرژی بالای ۳٫۴kHz در برابر تقریباً صفرِ دو فایل دیگر)، پیک دیکد‌شده ۲٫۰۳ یعنی کلیپ شده. کلی خط عمودی تمام‌باند (ترق‌تروق ضربه‌ای). ناحیه‌ی **موسیقی/تون انتظار در ثانیه ۹۰ تا ۱۳۵**. |
| `4.mp3` | ۱۵۴ ثانیه | باند تلفنی (~۰٫۴٪ بالای ۳٫۴kHz)، سکوت‌های پراکنده (~۲۱٪)، چند کلیک سخت، و یک **تون مزاحم ماندگار در ۲۹۶۶ هرتز**. |

ابزار مهم این مرحله علاوه بر اسپکتروگرام، **طیفِ میانه** (median spectrum) بود: از قدر مطلق STFT روی محور زمان «میانه» می‌گیریم. چون گفتار دائم عوض می‌شه، در میانه‌گیری محو می‌شه؛ ولی هر چیز **ثابت** (هوم برق، تون انتظار) به‌صورت قله‌ی تیز باقی می‌مونه. با همین روش پیدا کردیم:

- خط ~۴۸–۵۰ هرتز (هوم برق شهر) در هر سه فایل + یک هارمونیک مرتبه‌پایین حوالی ~۲۴۲/۲۵۳ هرتز (≈ ۵×۵۰؛ خوانش فرکانس‌ها به رزولوشن ~۵٫۴ هرتزیِ FFT گرد می‌شود) — همه زیر ۳۰۰ هرتز، پس فیلتر میان‌گذر حذفشون می‌کنه.
- تون‌های داخل باند: ۲۹۶۶ هرتز در `4.mp3` و ۲۴۴۴ هرتز در `3.mp3` — این‌ها داخل باند گفتارن و باید ناچ بخورن.
- داخل ناحیه موسیقیِ `3.mp3`: تون‌های کشیده‌ی ~۲۱۴۳ و ~۲۲۴۵ هرتز (اسکلت تونال آهنگ انتظار).

## ۲.۳ معماری خط لوله — ۹ مرحله و چراییِ ترتیبش

```
لود → ۱.نرمال‌سازی پیک → ۲.میان‌گذر ۳۰۰-۳۴۰۰ → ۳.ناچِ تون‌های ماندگار →
۴.محدودکننده‌ی تطبیقی کلیک → ۵.تفریق طیفی → ۶.سرکوب موسیقی انتظار (فقط جایی که هست) →
۷.تحلیل اکو → ۸.VAD و حذف سکوت → ۹.نرمال‌سازی RMS
```

نکته‌ی ترتیب: **اول تمیز می‌کنیم بعد VAD می‌زنیم** — چون بعد از نویززدایی کنتراست گفتار/سکوت بیش از ۲۰dB بیشتر می‌شه و آستانه‌گذاری VAD قابل‌اعتماد می‌شه. نرمال‌سازی هم آخره چون هر مرحله‌ی حذف، سطح سیگنال رو تغییر می‌ده.

### مرحله ۱ — نرمال‌سازی پیک

دیکدر MP3 برای `3.mp3` نمونه‌هایی تا ۲٫۰۳ برمی‌گردونه (بیرون بازه‌ی [1,1-])! اول همه رو به پیک ۰٫۹۵ مقیاس می‌کنیم تا آستانه‌های مراحل بعد روی مقیاس یکسان کار کنن.

### مرحله ۲ — فیلتر میان‌گذر باترورث ۳۰۰–۳۴۰۰ هرتز

- **چرا؟** هر چی بیرون این باند هست به‌قطع گفتارِ تلفنی نیست: زیر ۳۰۰ هرتز هوم و لرزش، بالای ۳٫۴kHz هیس و آشغال پهن‌باند (در `3.mp3` یعنی حذف یکجای ~۵٪ انرژی سیگنال + بخش بزرگی از ترق‌تروق پهن‌باند).
- **چطور؟** `scipy.signal.butter(4, [300, 3400], 'bandpass', output='sos')` + `sosfiltfilt` (فاز صفر — بخش ۱.۶).
- **اثر اندازه‌گیری‌شده:** SNR تخمینی `3.mp3` از ۱۲ به ~۳۰ دسیبل پرید.

### مرحله ۳ — ناچِ خودکار تون‌های ماندگار داخل باند

- **چرا؟** تون ۲۹۶۶ هرتزیِ `4.mp3` داخل باند عبوره؛ میان‌گذر نمی‌تونه حذفش کنه. سوت ممتد در پس‌زمینه‌ی کل مکالمه شنیده می‌شه.
- **چطور؟** از طیف میانه (بخش ۲.۲) هر قله‌ی با برجستگی ≥ ۱۰dB در بازه ۳۱۰ تا ۳۳۹۰ هرتز رو به‌عنوان تداخل شناسایی می‌کنیم — گفتار هیچ‌وقت در طیفِ میانه‌ی چند دقیقه صوت قله‌ی تیز نمی‌سازه چون فرمنت‌هاش مدام جابه‌جا می‌شن. بعد برای هر تون یک `iirnotch` با Q=35 اعمال می‌کنیم.
- **نتیجه‌ی تشخیص:** `2.mp3`: هیچ؛ `3.mp3`: ۲۴۴۴ هرتز؛ `4.mp3`: ۲۹۶۶ هرتز.

### مرحله ۴ — محدودکننده‌ی تطبیقی ترنزینت (de-click)

- **چرا؟** کلیک‌ها نمونه‌هایی هستن که نسبت به سطح **محلی** سیگنال سر به فلک می‌کشن. آستانه‌ی سراسری جواب نمی‌ده: توی فایلی که کلاً آرومه، گفتارِ بلند رو هم می‌بُره و برعکس.
- **چطور؟** RMS غلتان با پنجره ۲۰۰ میلی‌ثانیه می‌گیریم؛ هر نمونه‌ای که از ۵ برابر RMS محلی بیشتر شد، به‌نرمی فشرده می‌شه (بالای آستانه فقط ۱۵٪ اضافه رو نگه می‌داریم).
- **اثر:** حدود ۰٫۰۳ تا ۰٫۰۶ درصد نمونه‌ها در هر فایل محدود شدن — یعنی فقط خود کلیک‌ها، نه گفتار.

### مرحله ۵ — تفریق طیفی (Spectral Subtraction)

مهم‌ترین مرحله‌ی نویززدایی؛ فرمولش را بفهم:

```
|X̂clean[k,m]| = max(|X[k,m]| − α·|N̂[k]| ,  β·|N̂[k]|)
```

- **ایده:** نویز ایستا طیفِ تقریباً ثابتی داره. اگه طیف نویز `|N̂|` رو تخمین بزنیم، می‌تونیم از هر فریم STFT کمش کنیم و با **فازِ همان فریم اصلی** سیگنال رو بازسازی کنیم (گوش به فاز حساس نیست).
- **تخمین نویز از کجا؟** میانگین ۵٪ کم‌انرژی‌ترین فریم‌ها — یعنی خودِ الگوریتم «سکوت‌ها» رو پیدا می‌کنه؛ چون هر فایل مکث دارد، همیشه نمونه‌ی نویز خالص داریم.
- **α=2 (فراتفریق):** نویز دور میانگینش نوسان می‌کنه؛ اگه فقط میانگین رو کم کنیم نصف نویز می‌مونه.
- **β=0.05 (کف طیفی):** نمی‌گذاریم هیچ بینی صفر مطلق بشه. اگه بشه، بین‌های تصادفی روشن/خاموش می‌شن و آرتیفکت معروف «**نویز موزیکال**» (جیرجیرهای رباتیک) تولید می‌شه؛ کفِ کوچک این رو ماسک می‌کنه.
- **اثر:** بزرگ‌ترین جهش SNR: مثلاً `2.mp3` حدود +۹dB و `3.mp3` حدود +۹dB دیگر روی میان‌گذر.

### مرحله ۶ — سرکوب موسیقی انتظار

دو زیرمسئله: **کجاست؟** و **چطور کمش کنیم؟**

- **تشخیص (کجاست؟):** ویژگی متمایز موسیقی نسبت به گفتار: نت‌های **کشیده و پایدار**. بردار «کروما» (انرژی ۱۲ کلاس نتی) رو فریم‌به‌فریم حساب می‌کنیم؛ در هر بلوک ۵ ثانیه‌ای، همبستگی کرومای فریم‌های متوالی رو میانگین می‌گیریم. گفتار ~۰٫۳ تا ۰٫۷ می‌ده (چون هر ~۱۰۰ میلی‌ثانیه فونم عوض می‌شه)، موسیقی/تون > ۰٫۸. بلوک‌های خیلی کم‌صدا رو هم کنار می‌گذاریم (سکوت هم «پایدار» به نظر می‌رسه!). طولانی‌ترین رشته‌ی بلوک‌های پایدار = ناحیه موسیقی. نتیجه: فقط `3.mp3` و دقیقاً ثانیه ۹۰ تا ۱۳۵.
- **سرکوب (چطور؟):** داخل ناحیه، طیف میانه تون‌های غالب رو نشون می‌ده — در اجرای نهایی: ~۲۱۴۳ و ~۲۲۴۵ هرتز (اسکلت آهنگ انتظار) به‌علاوه ۴۴۷ هرتز (≈ ۹×۵۰؛ هارمونیک نهم هومِ برق که در این ناحیه‌ی کم‌صدا از ماسک گفتار بیرون می‌زنه) و یک قله‌ی مرزی حوالی ~۲۵۵۰. این‌ها رو ناچ می‌کنیم و سیگنالِ ناچ‌شده رو **فقط در همان ناحیه** با کراس‌فید ۰٫۵ ثانیه‌ای جایگزین می‌کنیم — بقیه فایل دست نمی‌خوره.
- **صداقت علمی:** فیلتر LTI فقط «اسکلت تونال» موسیقی رو می‌تونه بردارد؛ بخش پهن‌باند موسیقی با گفتار هم در زمان هم در فرکانس هم‌پوشانه و جداسازی کاملش از عهده‌ی ابزارهای این درس خارجه (به مدل‌های source separation نیاز داره). صورت پروژه هم همین رو گفته: نمره به منطق رویکرد است نه حذف کامل.

### مرحله ۷ — تحلیل اکو

- **مدل:** بازتاب یعنی `y[n] = x[n] + α·x[n−D]` — سیستم FIR شانه‌ای با تابع تبدیل `H(z) = 1 + α·z^(−D)`.
- **تشخیص:** خودهمبستگی (autocorrelation) سیگنال در لگ D قله می‌سازه. لگ‌های ۴۰ تا ۵۰۰ میلی‌ثانیه رو با آزمون برجستگی (prominence ≥ 0.1) می‌گردیم؛ این‌طوری پریودیسیته‌ی زیر و بمی صدا (لگ < ۱۵ms) اشتباهی اکو حساب نمی‌شه.
- **حذف:** اگر D و α معلوم باشن، معکوسِ دقیق سیستم، فیلتر IIR بازگشتی `x̂[n] = y[n] − α·x̂[n−D]` است (چون α<1 پایداره).
- **یافته‌ی صادقانه:** در هر سه فایل واقعی **هیچ قله‌ای با برجستگی > ۰٫۱ وجود نداره** — اکوی گسسته‌ی قابل‌اندازه‌گیری در کار نیست. به‌جای «حذف اکوی ناموجود» (که فقط صدا رو خراب می‌کرد)، کل ماشینِ تشخیص-و-حذف رو روی **اکوی مصنوعی** (تأخیر ۱۸۰ms و α=0.45 تزریق‌شده روی صوت واقعی) اعتبارسنجی کردیم: تأخیر دقیقاً ۱۸۰ms تشخیص داده شد و فیلتر معکوس اکو رو تا حد خطای ماشین (۱۰⁻¹⁶) حذف کرد.

### مرحله ۸ — VAD (تشخیص فعالیت گفتاری) و حذف سکوت

الگوریتم انرژی-محور با چند تدبیر ضدخطا:

1. RMS هر فریم به dB.
2. کف نویز = صدک ۱۰ انرژی فریم‌ها؛ آستانه = کف + ۱۰dB (و نه پایین‌تر از بیشینه − ۴۵dB).
3. **فیلتر میانه ۷ فریمی** روی ماسک → پرش‌های تک‌فریمی حذف می‌شن (نسخه‌ی گسسته‌ی هیسترزیس؛ نه یک بلیپ گفتار حساب می‌شه نه یک مکث کوتاه وسط کلمه سکوت).
4. **گسترش (dilation) ~۱۰۰ms** به هر طرف → شروع/پایان آرام کلمات قیچی نمی‌شه.
5. **فشرده‌سازی مکث:** سکوت‌های بلندتر از ۰٫۳ ثانیه به ۰٫۳ ثانیه کوتاه می‌شن — نه حذف کامل، چون صوتِ کاملاً بی‌مکث غیرطبیعی و خسته‌کننده‌ست.
6. هر نقطه‌ی برش با **کراس‌فید ۱۰ms** — وگرنه در محل برش کلیک می‌شنوی.

نتیجه: `2.mp3` از ۲۱۴ به ~۱۸۵ ثانیه، `3.mp3` از ۱۸۸ به ~۱۵۵، `4.mp3` از ۱۵۴ به ~۱۴۶.

### مرحله ۹ — نرمال‌سازی بلندی (RMS)

بلندیِ ادراکی به RMS مربوطه نه پیک. همه‌ی خروجی‌ها رو به هدف 20- dBFS مقیاس می‌کنیم؛ ولی یک **محافظ ضدکلیپ** داریم: اگر پیک از ۰٫۹۹ رد بشه، بهره رو عقب می‌کشیم. برای `2.mp3` و `4.mp3` همین اتفاق افتاد (به ~22.5- dBFS رسیدن) — معامله‌ی آگاهانه: کمی بلندیِ کمتر در ازای صفر اعوجاج.

## ۲.۴ متریک‌ها — از کجا بفهمیم بهتر شد؟

- **تخمین SNR:** میانگین انرژی فریم‌های گفتار منهای کف نویز (صدک ۱۰) به dB. قبل از حذف سکوت حساب می‌شه (بعدش دیگه «سکوتی» نمونده که کف رو بسازه — اگر بعدش هم حسابش کنی عدد افت می‌کنه ولی این افتِ واقعی کیفیت نیست، مصنوع تعریف متریکه).
- **کسر سکوت:** درصد فریم‌های بیش از ۴۰dB زیر بلندترین فریم.
- **مدت، RMS، پیک:** برای نشان‌دادن اثر VAD و نرمال‌سازی.

# بخش ۳ — مسئله ۲: قطعه‌بندی شکستگی‌های چاه

## ۳.۱ صورت مسئله و تعاریف

تصویر «بازشده» (unwrapped) دیواره‌ی چاه: محور افقی = زاویه دور چاه (۰ تا ۳۶۰ درجه)، محور عمودی = عمق. نکته قشنگ هندسی: **شکستگی صفحه‌ای که استوانه چاه رو قطع کنه، در تصویر بازشده سینوسی دیده می‌شه** (برای همین `well2.png` پر از منحنی‌های سینوسی است).

- **شکستگی اصلی (باید نگه داریم):** منحنی‌های تیره‌ی **ضخیم** و **پیوسته** که تقریباً کل عرض تصویر رو طی می‌کنن.
- **شکستگی فرعی (باید حذف شه):** ترک‌های ریز، نازک، محلی و تکه‌تکه.
- **آرتیفکت مزاحم:** راه‌راهِ عمودی (خط‌های تیره‌ی نازک عمودی ناشی از ابزار تصویربرداری) به‌خصوص در نیمه چپ `Well1.jpg`.

## ۳.۲ ابزارهای تئوری

### مورفولوژی — فیلترهای min/max

با یک «عنصر ساختاری» (SE — پنجره‌ای با شکل مشخص مثل بیضی ۵×۵):

- **فرسایش (erosion):** هر پیکسل = کمینه‌ی همسایگی → نواحی سفید لاغر می‌شن.
- **گسترش (dilation):** بیشینه‌ی همسایگی → نواحی سفید چاق می‌شن.
- **بازکردن (opening) = فرسایش بعد گسترش:** هر ساختار سفیدِ **نازک‌تر از SE کاملاً پاک می‌شه**؛ ساختارهای ضخیم‌تر تقریباً دست‌نخورده می‌مونن. ← این دقیقاً «فیلتر ضخامت» ماست!
- **بستن (closing) = گسترش بعد فرسایش:** شکاف‌های **باریک‌تر از SE پر می‌شن**. ← برای اتصال دوباره‌ی تکه‌های شکستگی.
- **کلاه‌سیاه (black-hat) = closing(I) − I روی تصویر خاکستری:** به هر ساختار **تیره‌ی باریک‌تر از SE** پاسخ قوی می‌ده. با SE بیضی ۳۱×۳۱، هر شکستگی تیره تا ضخامت ~۳۱ پیکسل رو با تمام بدنه‌اش روشن می‌کنه. ← آشکارساز اصلی ما.

### چرا Sobel/Canny انتخاب نشدن؟ (در نوت‌بوک مقایسه‌ی تصویری هست)

Sobel و Canny **لبه** پیدا می‌کنن یعنی جای پرش روشنایی. یک نوار تیره‌ی ضخیم دو لبه داره: خروجی‌شون دو خط موازی با وسطِ خالیه؛ درحالی‌که ما کل «روبان» شکستگی رو می‌خواهیم. فیلتر Frangi (رگ‌یاب) به روبان جواب می‌ده ولی در آزمایش ما به راه‌راه عمودی هم به‌شدت جواب داد و روی ضخیم‌ترین شکستگی‌ها پاسخ توخالی داد. black-hat هم دقیقاً روبان کامل رو می‌ده هم در برابر راه‌راه (بعد از destriping) مقاومه — با آزمایش مقایسه‌ای انتخاب شد، نه سلیقه‌ای.

### CLAHE

اکولایز کردن هیستوگرام یعنی بازپخش سطوح روشنایی برای پرکردن کل بازه (افزایش کنتراست). نسخه‌ی **تطبیقی محدودشده (CLAHE)** این کار رو در کاشی‌های ۸×۸ جدا انجام می‌ده (چون نورپردازی اسکن یکنواخت نیست) و با «سقف برش» (clip limit) جلوی تقویت بیش از حد نویز رو می‌گیره. ما clip=1.5 (ملایم) گذاشتیم چون CLAHE تهاجمی، راه‌راه عمودی رو تشدید می‌کرد (اینو تجربی دیدیم).

### فیلتر میانه و ترفند destriping

فیلتر میانه ساختارهای کوچک‌تر از پنجره‌اش رو **کامل حذف** می‌کنه (بر خلاف بلور گاوسی که فقط تارشون می‌کنه) و لبه‌ی ساختارهای بزرگ رو تیز نگه می‌داره. دو بار استفاده کردیم:

- **میانه‌ی افقی ۱×۱۱:** فیلتر میانه هر ساختاری رو که کمتر از **نصف پنجره‌اش** رو پر کنه کاملاً حذف می‌کنه. راه‌راه عمودی فقط ۱–۳ پیکسل «پهنای افقی» داره (خیلی کمتر از نصفِ ۱۱) → کاملاً محو می‌شه؛ ولی روبان شکستگی که محلیاً پهنه، زنده می‌مونه. (destriping)
- **میانه‌ی ۹×۹:** اسپکل و — نکته‌ی مهم — **بیشترِ ترک‌های ریز رو همین‌جا از بین می‌بره** چون از پنجره نازک‌ترن. یعنی انتخابِ ضخامت از همین مرحله‌ی شدت شروع شده.

### آستانه‌گذاری هیسترزیس

مشکل آستانه‌ی واحد: شکستگی در نواحی کم‌کنتراست از آستانه پایین می‌افته و قطع می‌شه؛ آستانه رو که پایین بیاری نویز وارد می‌شه. راه‌حل (همونی که داخل Canny هم هست): دو آستانه — هر پیکسل بالای آستانه‌ی **قوی** (صدک ۹۵ پاسخ black-hat) قطعی است؛ پیکسل‌های بالای آستانه‌ی **ضعیف** (صدک ۸۳) فقط اگر **به یک پیکسل قوی متصل باشن** نگه داشته می‌شن. ادامه‌های کم‌رنگِ شکستگی‌های قوی زنده می‌مونن، نویزِ ایزوله نه.

### اجزای همبند (Connected Components)

هر مجموعه‌ی ماکسیمال از پیکسل‌های سفیدِ به‌هم‌چسبیده یک «مؤلفه» است با آمار (کادر محیطی، مساحت). ابزار آزمون نهایی پیوستگی.

## ۳.۳ خط لوله نهایی — مرحله به مرحله

```
خاکستری → CLAHE(1.5) → میانه افقی 1×11 → میانه 9×9
→ black-hat 31×31 → هیسترزیس (p83/p95)
→ opening 5×5 → فیلتر کشیدگی → closing 15×5
→ ماسکِ لینک (dilation 101×11) → CC و معیار عرض ≥ 25٪ → ماسک نهایی
```

### فیلتر شکل (کشیدگی) — نوآوری مفید این حل

بعد از opening هنوز لکه‌های جمع‌وجور نویز باقی می‌مونن (خوشه‌های ترک ریز که به هم چسبیدن). تمایز کلیدی: تکه‌ی شکستگی **کشیده** است (نسبت محور بزرگ به کوچکِ بیضیِ برازش‌شده ≥ ۳)، لکه‌ی نویز **جمع‌وجور**. با `regionprops` مؤلفه‌های غیرکشیده‌ی کوچک رو دور می‌ریزیم (مؤلفه‌های خیلی بزرگ مثل ناحیه‌ی washout رو نگه می‌داریم).

### آزمون پیوستگی با «ماسک لینک» — ظرافت اصلی

مشکل: در `Well1.jpg` حوالی ستون‌های ۷۰۰ تا ۱۳۰۰ یک نوار رنگ‌پریده هست که ابزار ثبت، کنتراستی توش ضبط نکرده (نقص داده، نه زمین‌شناسی). شبکه‌ی شکستگی اونجا «قطع» دیده می‌شه و هیچ مؤلفه‌ی واحدی کل عرض رو طی نمی‌کنه.

راه‌حل: ماسک تمیز رو با SE عریض ۱۰۱×۱۱ **فقط برای آزمون** گسترش می‌دیم («ماسک لینک») تا تکه‌های همراستا به هم بچسبن؛ آزمون عرض روی مؤلفه‌های ماسکِ لینک انجام می‌شه ولی **خروجی نهایی همون شکل‌های تیز و بدون گسترش** است (ماسک تمیز رو به مؤلفه‌های قبول‌شده محدود می‌کنیم).

**معیار: عرض کادر محیطی ≥ ۲۵٪ عرض تصویر.** چرا ۲۵ و نه ۹۰؟ چون گسست‌های واقعی (نوار شسته‌شده) شبکه‌ها رو دوپاره می‌کنن. عدد ۲۵٪ با حاشیه‌ی امن انتخاب شده: در هر دو تصویرِ نمره‌دار، شبکه‌های واقعی ۳۰ تا ۱۰۰٪ عرض دارن و بزرگ‌ترین خوشه‌ی نویز فقط ۹ تا ۱۳٪ — یعنی فاصله‌ی تمیز بین «قبول» و «رد». به‌علاوه «پوشش ستونی» (درصد ستون‌هایی که حداقل یک شکستگیِ نگه‌داشته ازشون می‌گذره) رو به‌عنوان سنجه‌ی کمّی پیوستگی گزارش می‌کنیم.

# بخش ۶ — پرسش‌های احتمالی و پاسخ‌ها (برای دفاع)

**س: چرا باترورث و نه چبیشف/بیضوی؟**
ج: باترورث در باند عبور «حداکثر تخت» است — هیچ ریپلی ندارد، پس طیف گفتار را رنگ نمی‌کند. چبیشف/بیضوی گذار تیزتری دارند ولی به قیمت ریپل. اینجا گذار تیز لازم نیست (بین ۳٫۴k و محتوای بعدی فاصله زیاد است)، پس تختی مهم‌تر است.

**س: `sosfiltfilt` چی کار می‌کنه و چرا به جای `lfilter`؟**
ج: فیلتر را رفت و برگشت اعمال می‌کند → فاز صفر (هیچ جابه‌جایی/کجی زمانی)، دامنه دو بار اعمال می‌شود. چون پردازش آفلاین است مجازیم. `sos` هم یعنی پیاده‌سازی مقاطع مرتبه‌دو برای پایداری عددی فیلترهای مرتبه‌بالا.

**س: در تفریق طیفی چرا فاز را دست نمی‌زنید؟**
ج: گوش انسان به طیف دامنه بسیار حساس‌تر از فاز است؛ تخمین فاز تمیز هم اساساً سخت است. استاندارد این روش: دامنه‌ی اصلاح‌شده + فاز نویزی اصلی.

**س: نویز موزیکال چیست؟**
ج: وقتی تفریق طیفی بین‌هایی را به صفر می‌رساند، بین‌های منفرد به‌طور تصادفی بین صفر و مقدار مثبت نوسان می‌کنند و مثل جیرجیرهای کوتاه رباتیک شنیده می‌شوند. کف طیفی β جلوی صفر مطلق را می‌گیرد و ماسکش می‌کند.

**س: VAD شما با چه منطقی آستانه می‌گذارد؟**
ج: آستانه نسبی است نه مطلق: کف نویز (صدک ۱۰ انرژی فریم‌ها) + ۱۰dB. چون بعد از نویززدایی اعمال می‌شود، فاصله گفتار/سکوت بزرگ است و آستانه حساس نیست. فیلتر میانه نقش هیسترزیس، dilation نقش محافظ لبه کلمات، و فشرده‌سازی مکث (نه حذف کامل) طبیعی بودن را حفظ می‌کند.

**س: چرا اکو حذف نکردید؟ نمره‌اش را از دست نمی‌دهید؟**
ج: چون اکویی وجود ندارد — خودهمبستگی هیچ قله‌ای با برجستگی معنادار در ۴۰ تا ۵۰۰ms ندارد و «حذف» اکوی ناموجود فقط سیگنال را خراب می‌کرد. روش کامل تشخیص+حذف را پیاده و روی اکوی مصنوعیِ تزریق‌شده اثبات کردیم (بازیابی دقیق تأخیر، حذف تا 1e-16). روبریک صراحتاً می‌گوید نمره به «تلاش و منطق رویکرد» است.

**س: تشخیص موسیقی انتظار چطور کار می‌کند و چرا فلتنس طیفی نه؟**
ج: معیار ما پایداری زمانی کروماست (موسیقی نت‌های کشیده دارد، گفتار هر ~۱۰۰ms عوض می‌شود). فلتنس طیفی برای تفکیک «تونال از نویزی» است؛ هم موسیقی و هم گفتارِ واکه‌دار تونال‌اند، پس تمایز خوبی نمی‌دهد. پایداری زمانی تمایز اصلی است.

**س: چرا black-hat به‌جای Canny/Sobel/Frangi؟**
ج: (بخش ۳.۲ همین سند) Canny/Sobel لبه می‌دهند نه روبان؛ خروجی‌شان برای «حفظ ساختارهای ضخیم» مستقیماً قابل استفاده نیست. Frangi در آزمایش ما به راه‌راه عمودی حساس بود و روی ضخیم‌ترین شکستگی‌ها پاسخ توخالی داد. مقایسه‌ی تصویری چهار روش در §2.3 نوت‌بوک هست — انتخاب تجربی و مستند است.

**س: SE ۳۱×۳۱ از کجا آمد؟**
ج: از EDA: ضخامت شکستگی‌های اصلی بعد از پیش‌پردازش ~۵ تا ۱۵ پیکسل است؛ SE باید از ضخیم‌ترین شکستگی بزرگ‌تر باشد تا black-hat کل روبان را روشن کند (و از نوار ۱۰۰ پیکسلی بستر بزرگ‌تر نباشد تا آن را نگیرد).

**س: چرا معیار پیوستگی ۲۵٪ عرض است و نه «کل عرض»؟**
ج: چون در `Well1.jpg` یک نوار عمودی رنگ‌پریده (نقص ثبت داده) شبکه را واقعاً دوپاره کرده. ۲۵٪ با حاشیه انتخاب شده: شبکه‌های واقعی ≥ ۳۰٪ و بزرگ‌ترین نویز ≤ ۱۳٪. سنجه‌ی مکمل «پوشش ستونی» (۸۸٪ و ۹۸٪) هم گزارش می‌شود که همان «عبور از عرض تصویر» را کمّی می‌کند.

**س: پارامترها را چطور انتخاب کردید؟ دستی؟**
ج: همه از اندازه‌گیری‌های EDA آمده‌اند (باند ۳۰۰–۳۴۰۰ از استاندارد تلفن و طیف‌ها؛ فرکانس ناچ‌ها از قله‌های طیف میانه؛ صدک‌های هیسترزیس و اندازه SEها از ضخامت‌های مشاهده‌شده) و ثابت بودن‌شان با اجرا روی ۸ تصویر اضافی (بدون تغییر پارامتر) اعتبارسنجی شده.

**س: (تله!) اگر بگویند SNR شما بعد از VAD کم شده؟**
ج: تعریف متریک ما کف نویز را از صدک ۱۰ می‌گیرد؛ وقتی سکوت حذف شود صدک ۱۰ دیگر «نویز خالص» نیست و بالا می‌رود، پس SNR ظاهری افت می‌کند. متریک قبل از VAD معیار مقایسه‌ی درست است — این را در نوت‌بوک هم توضیح داده‌ایم.

# بخش ۷ — واژه‌نامه

| انگلیسی | فارسی / توضیح یک‌خطی |
|---|---|
| Sample rate (fs) | نرخ نمونه‌برداری؛ تعداد نمونه در ثانیه |
| Nyquist | نصف نرخ نمونه‌برداری؛ سقف فرکانس قابل نمایش |
| dBFS | دسیبل نسبت به تمام‌مقیاس (۱٫۰) |
| RMS | جذر میانگین مربعات؛ معادل «بلندی مؤثر» |
| STFT | تبدیل فوریه کوتاه-زمان؛ فوریه‌ی پنجره‌به‌پنجره |
| Spectrogram | نمایش تصویری |STFT|؛ زمان-فرکانس-شدت |
| Stationary / non-stationary | مانا (آمار ثابت در زمان) / نامانا |
| Band-pass | فیلتر میان‌گذر |
| Butterworth | فیلتر با باند عبور حداکثر-تخت |
| Zero-phase (filtfilt) | اعمال رفت‌وبرگشتی فیلتر؛ بدون اعوجاج فاز |
| SOS | مقاطع مرتبه دو؛ پیاده‌سازی پایدار فیلتر |
| Notch (iirnotch) | فیلتر حذف باریک یک فرکانس؛ پهنا = f0/Q |
| Spectral subtraction | تفریق طیفی؛ کم‌کردن طیف نویز از هر فریم |
| Over-subtraction (α) | ضریب فراتفریق برای پوشش نوسان نویز |
| Spectral floor (β) | کف طیفی؛ جلوگیری از صفر شدن و نویز موزیکال |
| Musical noise | آرتیفکت جیرجیر رباتیکِ تفریق طیفی تهاجمی |
| VAD | تشخیص فعالیت گفتاری |
| Hysteresis | دو-آستانه‌ای؛ ضد نوسان دور یک آستانه |
| Autocorrelation | خودهمبستگی؛ شباهت سیگنال با نسخه تأخیریافته‌اش |
| Comb filter | فیلتر شانه‌ای `1 + αz^(−D)`؛ مدل اکو |
| Chroma | بردار انرژی ۱۲ کلاس نتی |
| CLAHE | اکولایز تطبیقی محدودشده هیستوگرام |
| Median filter | فیلتر میانه؛ حذف کامل ساختارهای کوچکتر از پنجره |
| Morphology | مورفولوژی؛ فیلترهای min/max با عنصر ساختاری |
| Erosion / Dilation | فرسایش / گسترش |
| Opening / Closing | بازکردن (حذف نازک‌ها) / بستن (پرکردن شکاف‌ها) |
| Black-hat | closing(I) − I؛ آشکارساز ساختارهای تیره باریک |
| Structuring element (SE) | عنصر ساختاری؛ پنجره‌ی شکل‌دار مورفولوژی |
| Ridge vs Edge | ریج/روبان (کل نوار) در برابر لبه (مرز پرش) |
| Frangi | فیلتر رگ‌یابی مبتنی بر هسیان |
| Connected components | اجزای همبند + آمار کادر/مساحت |
| Regionprops / elongation | ویژگی‌های ناحیه؛ کشیدگی = نسبت محورهای بیضی برازش |
| Bounding box | کادر محیطی |
| Column coverage | درصد ستون‌های پوشش‌داده‌شده توسط ماسک نهایی |
